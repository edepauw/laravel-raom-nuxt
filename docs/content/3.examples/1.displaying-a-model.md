A detail page: fetch a single resource by its primary key, then render its **fields** (never the instance itself).

```vue [pages/reports/[id].vue]
<script setup lang="ts">
const route = useRoute()

// findByKey throws if the record doesn't exist — turn that into a 404
const report = await Report.query()
  .include('creator')
  .include('status')
  .findByKey(Number(route.params.id))
  .catch(() => {
    throw createError({ statusCode: 404, statusMessage: 'Report not found', fatal: true })
  })
</script>

<template>
  <article>
    <h1>{{ report.title }}</h1>

    <p class="text-muted">
      by {{ report.creator?.name }} · {{ report.status?.label }}
    </p>

    <time :datetime="report.created_at">
      {{ new Date(report.created_at).toLocaleDateString() }}
    </time>
  </article>
</template>
```

::note
`Report` is **auto-imported** — the module registers everything under your `models/` directory, so you never import model classes by hand.
::

## Why no `useAsyncData`?

Calling `.get()` / `.findByKey()` directly at the top of `<script setup>` is correct here — **don't** wrap it in `useAsyncData`:

- The package already de-duplicates the SSR and client fetch through its own payload cache, so you won't double-fetch on hydration.
- A hydrated model instance is **not serializable**; returning one from `useAsyncData` would break the Nuxt payload.

See [Lists, SSR & identity](/guide/lists-ssr-and-identity) for the full reasoning.

## Render fields, not the instance

```vue
<!-- Don't: breaks SSR / prints [object Object] -->
{{ report }}
<pre>{{ JSON.stringify(report) }}</pre>

<!-- Do: render plain field values -->
{{ report.title }}
{{ report.creator?.name }}
```

Field and relation access (`report.title`, `report.creator?.name`) reads identically on the server (raw data) and the client (hydrated instance) — only instance **methods** (`save`, `getKey`, …) are client-only.
