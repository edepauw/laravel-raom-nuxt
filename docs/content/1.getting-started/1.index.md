`laravel-raom-nuxt` (**R**EST **A**PI **O**bject **M**apper) is a Nuxt module that gives you an ORM-like developer experience over a [`lomkit/laravel-rest-api`](https://github.com/lomkit/laravel-rest-api) backend.

Traditional ORMs abstract a SQL database. This package applies the same idea to REST resources: models talk to an HTTP API instead of a DB. The transport changes (SQL → HTTP), but the developer model stays familiar.

```ts
const [reports, pagination] = await Report.query()
  .where('creator.id', currentUser.getKey())
  .include('status')
  .orderBy('created_at', 'desc')
  .limit(25)
  .get()
```

## Why a model layer

::card-group
  :::card
  ---
  icon: i-lucide-box
  title: Single source of truth
  ---
  Endpoint, fields, key, relations and pagination limits are declared once on the model. Calls elsewhere stay short and uniform.
  :::

  :::card
  ---
  icon: i-lucide-search
  title: Payloads done right
  ---
  The query builder produces the exact `{ filters, includes, scopes, instructions }` shape lomkit expects — building that by hand is error-prone and bypasses type-safety.
  :::

  :::card
  ---
  icon: i-lucide-link
  title: Mutations handled
  ---
  `attach` / `detach` / `sync` / `toggle`, nested `create`, and the `{ created, updated }` return shape are driven through the model in a single round-trip.
  :::

  :::card
  ---
  icon: i-lucide-fingerprint
  title: Consistent state
  ---
  An identity map maps one primary key to one in-memory instance, so a change made in one place is visible everywhere.
  :::
::

## The rule

If the backend is `lomkit/laravel-rest-api`, **every API interaction goes through a Model** — no `$fetch`, no `useFetch`, no `axios`, no hand-built lomkit payloads. If a model for the resource doesn't exist yet, create it first; declaring one is cheap and pays for itself the second time the resource is touched.
